**pipelines/compare.py — parallel comparison execution (per D-10, D-11, D-14):**
- Import `asyncio`, `concurrent.futures.ThreadPoolExecutor`, `dataclasses`
- Import `from pipelines.query import QueryResult, run_query`
- Import `from core.retriever import retrieve`
- Import `from core.vectorstore import VectorStore`
- Import `from core.llm_client import NIMClient`

Create `ComparisonResult` dataclass (per D-12):
```python
@dataclass
class ComparisonResult:
    result_large: QueryResult
    result_small: QueryResult
```

Create `run_comparison(question, vectorstore, nim_client, large_model, small_model, n_results=5, doc_id=None) -> ComparisonResult` (per D-10, D-11):
- Retrieve chunks ONCE (shared) using `retrieve()` — do NOT call run_query which retrieves separately (per D-11)
- Instead, build the prompt from the shared chunks, then call nim_client.chat() with each model in parallel
- Actually, for simplicity and code reuse, pass the shared chunks to `run_query` — but `run_query` currently retrieves its own chunks. So create a helper `_run_query_with_chunks(question, chunks, nim_client, model)` that takes pre-retrieved chunks and does the prompt→LLM→parse→validate flow. OR simply call run_query twice with the same inputs (both will retrieve the same chunks — acceptable for a concept demo).
- **Recommended approach:** Call `run_query(question, vectorstore, nim_client, model=large_model)` and `run_query(question, vectorstore, nim_client, model=small_model)` in parallel. Both retrieve the same chunks independently — acceptable overhead for 2 calls in a concept demo.
- Use `asyncio.run()` wrapping `asyncio.gather()` with `loop.run_in_executor(ThreadPoolExecutor(max_workers=2))` to dispatch both sync run_query calls to separate threads (per D-10)
- No `@st.cache_data` decorator on this function (per D-14)
- Temperature hardcoded to 0.3 for both (per D-11, consistent with existing pattern)
