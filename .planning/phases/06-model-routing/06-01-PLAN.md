Create `routers/__init__.py` (empty).

Create `routers/model_router.py` with:
- `TaskType` enum: `QA = "qa"`, `SUMMARY = "summary"`, `GRAPH_EXTRACT = "graph_extract"` (per D-01)
- `RouteDecision` dataclass: `model: str`, `reason: str` (per D-01)
- `route(task: TaskType, settings_large_model: str, settings_route_model: str, doc_length: int = 0, chunk_count: int = 0) -> RouteDecision` pure function (per D-01, D-02, D-03):
  - If `task == TaskType.GRAPH_EXTRACT` → return large model with reason about JSON-mode reliability
  - If `doc_length > 10_000 or chunk_count > 15` → return large model with reason about document size
  - Otherwise → return route model with reason about faster response for short tasks
- Model names are NEVER hardcoded — they come from the `settings_large_model` and `settings_route_model` parameters (per D-03)
- The `reason` string must be human-readable and include the specific signal that triggered the decision (per ROUTE-05)

Create `tests/test_model_router.py` with unit tests:
- `test_graph_extract_always_large`: route(GRAPH_EXTRACT, ...) returns large model regardless of doc_length
- `test_large_doc_uses_large_model`: doc_length > 10000 → large model
- `test_many_chunks_uses_large_model`: chunk_count > 15 → large model
- `test_short_qa_uses_route_model`: short doc QA → route model
- `test_short_summary_uses_route_model`: short doc summary → route model
- `test_reason_is_nonempty_string`: every route call returns non-empty reason
- `test_model_names_come_from_params`: verify returned model matches injected param, not hardcoded

| NIM API → response.usage | Token counts come from external API response |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-06-02 | Information Disclosure | response.usage | accept | Token counts are not sensitive. Usage data displayed intentionally as a feature. |
